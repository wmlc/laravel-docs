<a name="introduction"></a>
## 简介

Laravel 的「契约」（Contract）是一组接口，定义了框架提供的核心服务。例如，`Illuminate\Contracts\Queue\Queue` 契约定义了将任务加入队列所需的方法，而 `Illuminate\Contracts\Mail\Mailer` 契约定义了发送邮件所需的方法。

每个契约都有框架提供的对应实现。例如，Laravel 提供了支持多种驱动的队列实现，以及由 [Symfony Mailer](https://symfony.com/doc/current/mailer.html) 驱动的邮件实现。

所有 Laravel 契约都位于[它们自己的 GitHub 仓库](https://github.com/illuminate/contracts)中。这为所有可用契约提供了快速参考，同时也是一个独立、解耦的包，在构建与 Laravel 服务交互的扩展包时可以直接使用。

<a name="contracts-vs-facades"></a>
### 契约与 Facade 的对比

Laravel 的 [Facade](/docs/{{version}}/facades) 和辅助函数提供了一种简单的方式来使用 Laravel 的服务，无需在服务容器中类型提示并解析契约。在大多数情况下，每个 Facade 都有一个等效的契约。

Facade 不要求你在类的构造函数中引入它，而契约则允许你为类定义显式依赖。有些开发者喜欢以这种方式显式定义依赖，因此更倾向于使用契约；也有些开发者则喜欢 Facade 带来的便利。**一般而言，大多数应用在开发过程中使用 Facade 都不会有问题。**

<a name="when-to-use-contracts"></a>
## 何时使用契约

选择契约还是 Facade，取决于个人喜好和开发团队的品味。契约和 Facade 都可以用来构建健壮、经过充分测试的 Laravel 应用，二者并不互斥。你的应用中某些部分可以使用 Facade，另一些部分则依赖契约。只要你保持类的职责单一，你会发现使用契约和 Facade 在实际开发中几乎没有区别。

总体来说，大多数应用在开发中使用 Facade 都没有问题。如果你在构建一个与多个 PHP 框架集成的扩展包，可能会希望使用 `illuminate/contracts` 包来定义与 Laravel 服务的集成，而无需在扩展包的 `composer.json` 文件中引入 Laravel 的具体实现。

<a name="how-to-use-contracts"></a>
## 如何使用契约

那么，如何获取契约的实现呢？其实非常简单。

Laravel 中许多类型的类都是通过[服务容器（Service Container）](/docs/{{version}}/container)解析的，包括控制器、事件监听器、中间件、队列任务，甚至是路由闭包。因此，要获取契约的实现，只需在被解析类的构造函数中对接口进行「类型提示」即可。

例如，来看看下面这个事件监听器：

```php
<?php

namespace App\Listeners;

use App\Events\OrderWasPlaced;
use App\Models\User;
use Illuminate\Contracts\Redis\Factory;

class CacheOrderInformation
{
    /**
     * 创建事件监听器。
     */
    public function __construct(
        protected Factory $redis,
    ) {}

    /**
     * 处理事件。
     */
    public function handle(OrderWasPlaced $event): void
    {
        // ...
    }
}
```

当这个事件监听器被解析时，服务容器会读取该类构造函数上的类型提示，并注入相应的值。想了解更多关于在服务容器中注册绑定的内容，请查阅[服务容器文档](/docs/{{version}}/container)。
